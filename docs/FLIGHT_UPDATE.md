# Six-position flight update

The existing `MotionController` still owns the single wander timeout, dragging, native frame loop, interruption, pinning and cleanup. Its destination selection now calls pure helpers in `shared/flight.ts`, which calculate six semantic destinations from the current display’s work area and actual window size. Selection excludes the nearest/current position and the previous departure when alternatives exist. No automatic destination uses arbitrary X/Y randomness. Display changes reset history; manual dragging never snaps to a stop.

The existing numeric `movementSpeed` preference is extended to 0.5–10, preserving saved speeds and avoiding duplicate state. Finite out-of-range saved values clamp; invalid IPC values are rejected. The 30-second default interval remains unchanged.

Main sends a typed `Flight` descriptor through the existing snapshot subscription at launch, phase changes, cancellation and completion. It includes the start timestamp, travel and settle durations, direction, destination and speed. Both native interpolation and renderer animation use this timeline. No per-frame React state updates or new privileged renderer API are needed. Missing an intermediate phase notification does not skip its animation: Three.js samples elapsed progress directly at render time.

The native window follows cubic deceleration along a wide cubic Bezier sweep, ending at the exact destination. Main selects the sign with the most inward clearance and scales the first control's perpendicular offset with distance and display size, up to 700px. The control's projection stays at 28% of the route; the second control is on the direct route at 76%. Keeping those projections ordered guarantees forward progress without circling in place. The second control makes the endpoint tangent align exactly with the direct approach. The bounded controls keep the complete curve inside the work area. Both immutable control points are shared in the flight snapshot, so the native window and renderer use identical geometry.

The outer model rig uses ZXY Euler order. Screen-plane heading aligns local +Y (the upper-body axis) to the analytic Bezier tangent, pitch gives depth, and local Y rotation performs a true barrel roll around that aligned axis. This keeps the head leading throughout the 360° roll rather than spinning an upright robot. Arms rise into forward flight and the rig shrinks by 8% during the pose to retain canvas margins. Heading is unwrapped against its launch angle to avoid jumps on vertical trajectories. The roll finishes by halfway, steering continues through 85%, and the pose returns to neutral smoothly by 94%. The trail follows the approach tangent. Idle body/head motion operates only on inner groups; no cursor code writes flight rotation. Every transform uses radians and the same timestamped session.

Landing uses the existing normalized flight progress, not another timer: the native window rises from 88% to 95%, then descends from 95% to 100%. Both lift segments use smoothstep so their velocity is zero at the joins and touchdown. Lift scales with window height (8–24px, normally 18px), limited by target-to-work-area-top clearance. It can occupy top edge padding while keeping the complete window visible. Zero overhead clearance safely suppresses lift. The original Bezier path is unchanged before this final overlay, and the exact endpoint is retained. The old model-only post-arrival bounce is removed; the existing 200–500ms stabilization remains quiet before the next countdown. Native updates briefly increase from 30 to 60fps during flight to sample the short landing at 10×, restoring the idle clock on completion or cancellation. Model flight also runs at 60fps, including battery mode, and rendering stops while hidden.

Reduced motion, DND, hidden windows, interaction, pinning, dragging and task-state blockers remain respected. Cancellation clears the flight descriptor and pending movement; screen geometry and secure IPC ownership checks remain in the main process.

Regression coverage includes the half-flight turn boundary at 0.5× and every integer multiplier through 10×, stable heading, early banking, monotonically decreasing arrival yaw, and direction-sensitive pose across every pair of stops. Native tests observe the default 30-second wait, exact destinations, and early turning before sustained flight at 1× and 10×. Speed persistence, timer interruption, destination exclusion, work-area boundaries and endpoint accuracy remain covered.
