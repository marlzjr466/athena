## Execution contract

An instruction succeeds when Athena can verify the requested change in the target application. For example, opening a URL through the operating system verifies that the OS accepted it. Verifying a video is paused requires reading the player state. The floating voice session and the selected text conversation have separate identities. Sending dictated text to a chat requires an explicit instruction and a resolved target conversation.

GPT-Live already delegated speech to the client. The selected-model planning path only had access to project tools. It could return conversational text without executing a registered desktop or internal action. Creating a voice-requested chat could also lose the active project. The implementation extends the existing native action registry and voice planner. Simple commands execute directly, and compatible reasoning models can call the same permission-checked actions for multi-step requests. [Registry](../electron/main/ai/nativeActionRegistry.ts) · [Voice planning](../electron/main/ai/voiceActionPlan.ts) · [GPT-Live client](../src/services/speech/livePeer.ts)

| Target | Execution and verification |
| --- | --- |
| Athena | Navigation uses a renderer acknowledgment. Project, chat, model, reasoning and draft actions use the existing state services. Chat submissions carry the message ID so completion can be associated with the original request. |
| Browser | New tabs use the selected window of the running browser. Native window commands verify the process, window, active tab and resulting tab count. An explicitly authorized loopback Chromium connection can use Playwright on the focused page. Without that connection, supported accessible page controls use the native adapter. A dedicated browser is available for separate sessions and file transfers. |
| Desktop | The macOS adapter uses Accessibility and the Windows adapter uses UI Automation and Win32. Installed applications can be authorized individually. Input requires a matching application and window. Inspecting a target can still fail if its application does not expose the requested control. |
| Vision | Selected-window observation requires the existing capture permissions. A visual gesture is bound to the observed window, its geometry and pixels. Changed observations require a new capture. Sending a capture to an external model and executing an input gesture have separate approval checks. |
| Continuous control | Delegation IDs guard against repeated events. Stop, pause and corrections apply to pending work. An action already submitted to another application may finish. Receipts record the result, and late completions from superseded tasks are suppressed. |

Controls are in **Settings → AI → Computer use** and **Automation permissions**. The **Run test** button reads the active chat’s status through the registry. **Stop automation** cancels pending work. Desktop and screen permissions remain subject to the operating system.

## Platform limits

- macOS denied Screen Recording. The live desktop test covered Accessibility. Capture, visual click and drag were not verified against a real user window.
- Windows adapter checks used fixtures. Physical Windows applications, multiple-monitor DPI transitions and application elevation boundaries still require testing on Windows.
- An existing browser retains its profile and sign-ins. Availability of in-page controls depends on the exposed accessibility tree or an explicitly authorized connection. The dedicated browser has its own sign-ins. Tests used fixture content for page editing and an actual personal browser for tab management.
- The development Mac had one 2× Retina display. Second-display selection and ambiguity were covered with fixtures. Physical multi-monitor placement and full-screen behavior on other systems remain unverified.
- Complex model-driven planning requires a provider that accepts host-managed tools. Some native CLI or ACP sessions control their own tools. The local planning route remains available.
- Application-specific menus, protected fields, unsupported media controls and undo depend on what the target exposes. The complete example workflows were not all spoken end to end.
