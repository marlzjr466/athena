## Findings

The main process previously used one ChatController for control-center chat, floating input, tool narration, hands-free answers, and avatar activity. Its provider followed the global `aiMode`. Chat snapshots were broadcast to multiple windows, and phase/tool/completion callbacks directly drove the avatar. Speech had no explicit local execution ownership gate. Thus online responses could affect the floating companion, and switching the global provider changed what powered it.

The existing strict-offline setting was also reset when selecting an online provider. Full Mac Access is provider-bound; reusing its global-provider resolver for the new local lane would accidentally reuse an online grant.

## Implemented foundation

- Added explicit origin/session/correlation ownership to assistant executions and persisted message records. Missing ownership on historical messages is not fabricated.
- Added a local activity bridge that rejects online, training, unowned, other-session, retired, and superseded execution events.
- Removed online phase/tool/completion callbacks from the avatar and online snapshots from floating windows.
- Added a separate persistent companion conversation repository, workspace grants, attachments, tool-session bookkeeping, and context service under `userData/athena-local/companion`.
- Reused the existing ChatController, Ollama service, tool implementations, speech service, and avatar controller; no second inference server or avatar engine.
- Floating IPC resolves its conversation lane using trusted renderer identity, not a client-supplied provider. Online session IDs cannot mutate local conversations.
- Local provider construction uses only Ollama and rejects missing/mismatched models without cloud fallback. Local context cannot acquire OpenAI built-in search inference.
- Companion model changes select/create an associated companion session without rewriting another model's conversation history.
- Hands-free answers and floating input use the companion controller; online dictation remains online.
- Speech/narration reject nonlocal executions. Renderer speech subscriptions also require local ownership and matching session. Invalid speech requests cannot interrupt valid local playback.
- Floating open/close-chat commands target the local panel, and its folder picker routes to local context.
- Local filesystem access checks the explicit `local` provider grant, independently of the active online provider. Ordinary workspace grants and protected-resource checks remain in force.
- Local inference preferences and strict-offline preference survive online provider selection.
- Removed Ollama construction from the online provider factory and local-model selection from online conversation controls. Local settings now expose an independent active-companion-model selector.
- Legacy `aiMode: local` settings restore as `unconfigured` for online chat, preserving local model/settings and requiring an explicit online choice. No automatic paid-provider activation. Online status/model lookup does not query a provider while unconfigured.
- Online context, search tests, and sub-agent availability no longer inherit the local companion's strict-offline preference. Online configuration changes do not cancel local inference; local configuration changes do not cancel online inference.
- Added main-issued hands-free ownership leases tied to the companion session and local configuration. State, playback, synthesis, reply requests, and streaming progress reject missing/incorrect/expired ownership; microphone authorization is checked independently. Renderer subscriptions also check ownership. Local session/configuration changes reinitialize the hands-free lease.
- Closed a late-authorization race during floating-window unmount and local-session switches. Floating activation now names the expected local session; a stale renderer can release only its own main-issued lease, and delayed initial snapshots cannot restore an obsolete session.
